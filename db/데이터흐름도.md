# 설계문서작성 참고용 — 데이터 흐름도 및 DB 설계 근거

> 광주2_3조 goodBuy · 작성 : 김지영

---

## 1. 핵심 설계 원칙 — 거래내역을 저장하지 않는다

> **은행 거래내역은 민감한 개인 금융정보입니다.**
> goodBuy는 사용자의 이름과 거래 데이터를 서버에 저장하지 않습니다.
> DB에는 분류 기준(카테고리·키워드·이상치 임계값)만 보관하며,
> 사용자의 거래 데이터는 분석 처리 중 Backend 메모리에만 존재하다가 응답 후 소멸합니다.

| 구분 | 내용 |
|---|---|
| **DB에 저장** | 카테고리 9종 · 이상치 기준 금액 · 분류 키워드 553개 · GIF 주소 |
| **저장하지 않음** | 사용자 이름 · 거래 상대 · 거래 금액 · 분류 결과 · 이상치 판정 · 집계 결과 |

**설계상 이점**

1. **개인정보 최소 수집** — 저장하지 않으므로 유출될 개인정보가 존재하지 않습니다
2. **책임 분리** — DB는 기준 데이터의 정확성을, Backend는 분석 로직을 담당합니다
3. **기준 변경 즉시 반영** — 이상치 기준을 바꾸면 다음 분석부터 곧바로 적용됩니다

**설계상 제약 (의도된 것)**

- 분석 이력 조회 기능이 없습니다. 결과는 화면을 벗어나면 사라집니다.
- 사용자별 소비 추이 같은 기간 비교 기능은 이 구조에서 제공할 수 없습니다.

## 2. 전체 데이터 흐름 (설계문서에 넣을 그림)

```
[Frontend]
이름 입력 + 거래내역 이미지 업로드
    |
    | image + user_name
    v
[Backend]
image + user_name 수신
    |
    v
[Python OCR]
거래정보 추출
(counterparty, amount)
    |
    v
[Backend - In Memory]
    |
    +-- 1. 문자열 정규화
    |
    +-- 2. 자기이체 판별 및 제외
    |
    +-- 3. 카테고리 분류
    |
    +-- 4. 이상치 후보 탐지
    |
    +-- 5. 카테고리별 소비금액 / 비율 계산
    |
    +-- 6. 대표 소비 카테고리 선정
    |
    v
[Backend Response]
    |
    +-- 실제 소비내역
    +-- 카테고리별 금액 / 비율
    +-- 이상치 후보
    +-- 대표 GIF
    |
    v
[Frontend]
분석 결과 표시
    |
    +-- 실제 소비내역
    +-- 카테고리별 소비패턴
    +-- 이상치 거래 표시
    |      -> 사용자가 더치페이 여부 직접 판단
    |
    +-- 대표 소비패턴 GIF 표시


[Database - 기준 데이터]

categories
    +-- dutch_threshold
    +-- gif_url

category_rules
    +-- keyword x 553

※ 앱 시작 시 기준 데이터를 1회 조회
※ 거래 데이터 자체는 DB에 저장하지 않음
※ 응답 완료 후 거래 데이터는 메모리에서 소멸
```

## 3. ERD

```
┌────────────────────────────────┐
│ categories                     │
├────────────────────────────────┤
│ PK category_id          INT    │
│ UQ category_name        VARCHAR│   FOOD, TRANSPORT, LIVING ...
│    dutch_threshold      INT    │   이상치 판정 기준
│    gif_url              VARCHAR│   대표 카테고리 GIF
└───────────────┬────────────────┘
                │
                │ 1 : N
                ▼
┌────────────────────────────────┐
│ category_rules                 │
├────────────────────────────────┤
│ PK rule_id              INT    │
│ FK category_id          INT    │
│ UQ keyword              VARCHAR│   분류 키워드 (553건)
└────────────────────────────────┘
```

### 엔티티 정의

| Entity | Row 의미 | Entity로 구분한 이유 |
|---|---|---|
| `categories` | 소비 카테고리 1개 | 여러 분류 규칙에서 반복 참조되고, 카테고리별 이상치 기준과 GIF를 독립적으로 관리해야 함 |
| `category_rules` | 분류 키워드 1개 | 하나의 카테고리에 여러 키워드가 존재하므로 1:N으로 분리 (정규화) |

### 속성 정의

| Entity | Column | Type | Key/제약 | 의미 | 선정 이유 |
|---|---|---|---|---|---|
| `categories` | `category_id` | INT | PK, NOT NULL | 카테고리 고유 ID | 분류 규칙에서 카테고리를 참조하기 위해 |
| | `category_name` | VARCHAR(30) | UQ, NOT NULL | FOOD, TRANSPORT 등 | 동일 카테고리 중복 생성을 방지하고 Backend가 이름으로 조회하기 위해 |
| | `dutch_threshold` | INT | NOT NULL, `> 0` | 이상치 탐지 기준 금액 | 카테고리마다 다른 금액 기준으로 이상치 후보를 탐지하기 위해 |
| | `gif_url` | VARCHAR(255) | NOT NULL | 카테고리 대응 GIF 주소 | 대표 소비 카테고리에 맞는 GIF를 Frontend에 표시하기 위해 |
| `category_rules` | `rule_id` | INT | PK, NOT NULL | 분류 규칙 고유 ID | 각각의 키워드 규칙을 식별하기 위해 |
| | `category_id` | INT | FK, NOT NULL | 키워드가 속한 카테고리 | 하나의 카테고리에 여러 분류 키워드를 연결하기 위해 |
| | `keyword` | VARCHAR(50) | UQ, NOT NULL | 카테고리 분류용 키워드 | 정규화한 거래상대명에 키워드가 포함되는지 확인해 카테고리를 결정하기 위해 |

### 정규화 근거

카테고리와 키워드를 한 테이블에 두면 `FOOD` 라는 카테고리명과 기준 금액이 201번 반복 저장됩니다.
기준 금액을 한 번 바꾸려면 201개 행을 모두 수정해야 하고, 일부만 바뀌면 데이터가 불일치합니다.

```
[정규화 전]

김밥     FOOD     30000
칼국수   FOOD     30000
치킨     FOOD     30000
떡볶이   FOOD     30000
 ...      ...      ...

        ↓ 문제

FOOD, 30000이
키워드마다 반복 저장됨


        ↓ 1:N 분리


[정규화 후]

categories              category_rules

FOOD  30000  <--------- 김밥
       1                  칼국수
                          치킨
                          떡볶이
                          ...
                          201건
                           N


         categories  1 : N  category_rules
```

카테고리를 별도 엔티티로 분리해 **기준 금액과 GIF 주소를 한 곳에서만 관리**하도록 했습니다.

## 4. 데이터 추적 (trace-through)

화면에 표시되는 각 값이 어디에서 오는지에 대한 대응표입니다.

| 화면 표시 항목 | 출처 | DB 저장 |
|---|---|---|
| 거래 상대 (상호명) | OCR 결과 → Backend 메모리 | ✗ |
| 결제 금액 | OCR 결과 → Backend 메모리 | ✗ |
| 실제 소비 금액 | Backend 자기이체 판별 결과 | ✗ |
| 카테고리명 | `categories.category_name` | **✓** |
| 이상치 표시 | Backend 판정 결과 | ✗ |
| — 판정 기준값 | `categories.dutch_threshold` | **✓** |
| — 분류 근거 | `category_rules.keyword` | **✓** |
| 카테고리별 금액·비율 | Backend 집계 결과 | ✗ |
| 대표 카테고리 GIF | `categories.gif_url` | **✓** |
